# Сервис: max_bot

## Назначение

MAX-бот проекта «Пилот». Обслуживает роль ОТВЕТСТВЕННОЕ ЛИЦО: принимает
сообщения из мессенджера MAX и отправляет запросы к Django REST API
(`apps/django_site`).

Реализовано:

- long polling, роутинг, FSM (память или Redis), клиент к Django REST API;
- **экранная модель**: бот держит одно «живое» сообщение и редактирует его, а не шлёт новые
  (`bot/ui.py`, `bot/screens.py`). На нажатие кнопки сообщение заменяется через
  `POST /answers`; после текстового ввода редактируется «якорное» сообщение бота
  (`PUT /messages`), а если оно недоступно — отправляется новое;
- главное меню (`/menu`, кнопка «Начать»), у каждого экрана есть «Назад»/«Меню»;
  команды `/menu /reports /pilots /profile` регистрируются в меню «/» (`PATCH /me/commands`);
- регистрация одним сообщением с шагами 1–3, кнопки «Пропустить»/«Отмена»;
- профиль: кнопки «✏️ ФИО» / «✏️ О себе» / «Очистить» (команды `/name`, `/about` работают как раньше);
- пилоты: страницы по 5 с кнопками «◀ / ▶» в том же сообщении;
- отчёты: сразу открывается сегодняшний день, дни листаются «◀ 12.10 / 14.10 ▶», записи — «◀ Запись / Запись ▶»;
  фото прикрепляются картинками (по URL), видео — кнопками-ссылками; при ошибке MAX с картинками
  фото показываются ссылками;
- ошибка Django при нажатии кнопки не затирает экран, а показывает всплывающую подсказку;
- кнопки из старых сообщений и произвольный текст вне диалога ведут в меню (`bot/routers/fallback.py`);
- «печатает…» при командах, которые ходят в Django.

Исходящие вызовы MAX API (редактирование, ответ на кнопку, действия, команды) делает
`services/max_api.py` по `schema.yaml`; приём событий — по-прежнему `maxapi`.

**Не проверено на реальном боте** (в среде разработки не было сети и самого `maxapi`):
контакт-вложение (`_vcf_text`), порядок срабатывания роутеров (fallback должен срабатывать только
если ничего не подошло), доступность URL фото для серверов MAX (в проде это S3, в dev —
внутренний адрес `django_app`, там фото покажутся ссылками). Логику экранов и `Ui` проверяют
`python -m unittest discover -s tests` на заглушках.

## Стек

Python 3.12, [maxapi](https://github.com/love-apples/maxapi) (обёртка над
MAX Bot API в стиле aiogram), Redis (хранилище FSM, опционально).

## Переменные окружения

    | Переменная | Обязательна | Описание |
    MAX_BOT_TOKEN | да | Токен бота, выданный при создании бота в MAX |
    DJANGO_API_BASE_URL | да | Базовый URL Django REST API, например http://django_app:8000/api |
    BOT_TIMEZONE | нет | Часовой пояс для «сегодня/вчера» в отчётах, по умолчанию Europe/Moscow |
    MAX_API_BASE_URL | нет | Адрес MAX Bot API, по умолчанию https://platform-api2.max.ru |
    REDIS_URL | нет | URL Redis для хранения FSM, например redis://redis:6379/0. Если не задан — состояния хранятся в памяти процесса и теряются при перезапуске |

## Про long polling

Бот сам постоянно спрашивает MAX API, нет ли новых событий — поэтому не
нужен домен, HTTPS-сертификат и открытый порт. Это удобно для разработки
и небольшой нагрузки, но у long polling есть официальное предупреждение:
он ограничен по скорости и сроку хранения событий и **не рекомендуется
для production**. Для боевого окружения библиотека `maxapi` поддерживает
переключение на webhook (через aiohttp/FastAPI/Litestar) — дайте знать,
когда это понадобится, вернуть вебхук — дело нескольких строк в `main.py`.

Если у бота ранее были активные webhook-подписки, события не будут
приходить через polling, пока подписки не снять — `await bot.delete_webhook()`.

## Структура

    main.py                — точка входа: запуск long polling
    config.py               — конфигурация из переменных окружения
    bot/dispatcher.py       — сборка Bot/Dispatcher, подключение хранилища FSM
    bot/routers/common.py   — общие хендлеры (/start, /ping, приветствие)

## Локальный запуск (без Docker)

    pip install -r requirements.txt
    MAX_BOT_TOKEN=... DJANGO_API_BASE_URL=http://localhost:8000/api python main.py
