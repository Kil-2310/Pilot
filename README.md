# Pilot

## О проекте

Проект «Пилот» — это отечественная цифровая платформа для контроля и обеспечения прозрачности ухода за людьми, нуждающимися в помощи. Платформа решает проблему недобросовестного выполнения обязанностей волонтерами через обязательную фиксацию результатов работы (фото, видео, текстовые отчеты), минимизирует человеческий фактора, при уходе за нуждающимся, обеспечивает доверие между семьями и помогающими на расстоянии.

## Роли в системе

В проекте аредусмотрено 5 ролей:

1. Роль АДМИНИСТРАТОР - пользователь, имеющий полный контроль над системой.
2. Роль МЕНЕДЖЕР – группа пользователей, они могут добавлять новых пилотов в проект, а также удалять их, блокировать или временно приостанавливать доступ. Без их участия ни один новый пилот не может быть допущен к работе с сопровождаемыми.
3. Роль СОПРОВОЖДАЕМЫЙ - человек, который не может позаботиться о себе сам. Это может быть инвалид, пенсионер, человек, потерявший способность логически мыслить, или тот, кто в силу возраста либо состояния здоровья нуждается в постоянном присмотре и помощи в бытовых вопросах.
4. Роль ОТВЕТСТВЕННОЕ ЛИЦО - родственник или друг сопровождаемого, который берёт на себя формальную и моральную ответственность за его благополучие. Он выступает связующим звеном между сопровождаемым и пилотом: подтверждает необходимость помощи, согласовывает график визитов, получает отчёты о состоянии подопечного.
5. Роль ПИЛОТ - волонтёр осуществляющий контроль над сопровождаемым. Его задача — регулярно посещать подопечного, помогать ему в бытовых делах и фиксировать результаты своей работы в небольшом блоге внутри системы. В этом блоге пилот отмечает приём лекарств, общее самочувствие сопровождаемого, прикладывает фото убранной квартиры, купленных продуктов и других выполненных задач.

## Цель проекта

Цель проекта «Пилот» – cоздать безопасную систему взаимодействия семьи и волонтера, повысив качество жизни уязвимых категорий граждан и снизив тревожность их близких.

Проект призван решить проблему недобросовестного выполнения обязанностей некоторыми волонтерами, обеспечивая прозрачность, контроль и ответственность на всех этапах оказания помощи. Кроме того, родственники подопечных получают фото- и видеоматериалы о повседневной жизни, а также информацию о состоянии здоровья и самочувствии близкого человека — без необходимости вступать в прямой контакт с волонтером.

## Технологии и архитектура проекта

Проект состоит из 2-ух интерфейсов:
1. Веб-приложение предназначено для пилота: он регистрирует сопровождаемого, ведёт учёт своей работы а так же предоставляет API для MAX-бота.
Стек: Python, Django, Django Rest Framework, Celery, Rabbitmq, HTML5, CSS3, JavaScript.
2. MAX-бот ориентирован на ответственное лицо: через него можно зарегистрироваться в приложении, управлять своим аккаунтом, получать отчёты от пилота, а также просматривать доступных пилотов с фильтрацией по месту жительства.
Стек: Python, Redis, Maxapi.

Инфраструктура и данные:
- Хранение данных: Единая база данных PostgreSQL (в dev-режиме SQLite).
- Файлы: S3-хранилище (фото и видео) от Timeweb.
- Хостинг: Российский облачный провайдер Timeweb (для соблюдения ФЗ-152 о хранении персональных данных на территории РФ).
- Логирование: Grafana и Loki.
- Версионирование: Git с методологией Git Flow.

## Пользовательский сценарий

1. Старт. Менеджер вручную создает аккаунт пилота и передает ему доступы.
2. Регистрация ответственного лица. Ответственное лицо находит бота в MAX и проходит регистрацию.
3. Связка. Пилот через веб-интерфейс создает карточку сопровождаемого, заполняет чек-лист обязанностей (прием лекарств, уборка) и добавляет ответственное лицо.
4. Исполнение. Во время визита пилот открывает карточку визита (отчет) в веб-интерфейсе, отмечает выполненные пункты, загружает фото чистой квартиры и купленных продуктов, описывает настроение подопечного.
5. Информирование. Ответственное лицо в любой момент времени может получить сводку карточек визитов от пилота в MAX-боте.

## Инструкция по запуску и управлению локальной версии проекта через Docker Compose

### Установка ПО и настройка переменного окружения

1. Установить Docker по ссылке: https://docs.docker.com/engine/install/ и Docker Compose. Docker Compose обычно идет в связке с Docker.
2. Установить плагин для логирования: 
    ```bash
    docker plugin install grafana/loki-docker-driver:latest --alias loki --grant-all-permissions
    ```
3. Создайте в кроне проекта файл .env и заполните его по примеру ниже. 


      DJANGO_SECRET_KEY='django-insecure-fh_wan5bo5hvr=(7*y1jar%%a580e&mb_8n7i0lkskc^kl5hrp'
      DJANGO_DEBUG=1
      DJANGO_LOGLEVEL=INFO
      
      POSTGRES_USER=admin
      POSTGRES_PASSWORD=123
      POSTGRES_DB=pilot
      POSTGRES_PORT=5432
      
      RABBITMQ_USER=admin
      RABBITMQ_PASSWORD=123
      
      GF_USER=admin
      GF_PASSWORD=123

      MAX_BOT_TOKEN='Токен бота из MAX'
      DJANGO_API_BASE_URL='http://django_app:8000/api'
      REDIS_URL='redis://redis:6379/0'

### Запуск локального проекта

``` bash
docker compose --profile nginx up -d --build
```

### Остановка проекта

``` bash
docker compose down
```

- Описание MAX-бота находится в папке apps/max_bot.
